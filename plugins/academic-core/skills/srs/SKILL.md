# Задания СРС, практические и лабораторные

Задания строятся **из паспорта курса**: темы и часы (`topics`: `srs`, `practicals`,
`labs`, `content`, `lab`, `srs_task`, `srs_form`, `srs_due`), РО, ЦУР, оценивание, литература. Студенту — задание и критерии,
**не готовое решение**.

Говори на языке преподавателя (ru или ky), вопросы — по одному, с вариантом по умолчанию.

## 1. Что делаем

1. Найди `course.yaml`. Нет — `/academic-core:new-course`.
2. Спроси: «Какие задания: СРС, практические, лабораторные или все? (все)» и «по всем
   темам или по выбранным? (по всем)».
3. Есть `srs.yaml` — дополняй его, не перезаписывай готовое. Есть у преподавателя свои
   задания (docx/pdf) — извлеки текст
   (`uv run "${CLAUDE_PLUGIN_ROOT}/scripts/extract_text.py" "<файл>"`) и бери их за основу.

## 2. Напиши `srs.yaml` (в папке курса)

Формат — `references/srs-format.md`, образец — `templates/srs.example.yaml`.

Для каждого задания:

- `topic`, `week`, `kind` («СРС», «Практическое занятие», «Лабораторная работа»).
- `goal` — одна фраза: чему научится студент.
- `outcomes` — РО темы из паспорта (коды).
- `task` — что сделать, конкретно и проверяемо; для СРС — опора на `srs_task` темы,
  для лабораторной — на `lab`. Форма и срок — из `srs_form` и `srs_due`, если заданы.
- `steps` — 3–6 шагов выполнения.
- `submission` — форма сдачи (файл, отчёт, демонстрация, LMS) и объём.
- `deadline_week` — неделя сдачи (обычно следующая после темы; не позже последней недели).
- `hours` — часы из паспорта по этой теме и виду.
- `criteria` — 3–5 критериев, у каждого `points` и все четыре уровня
  (`excellent`, `good`, `satisfactory`, `poor`) — наблюдаемые признаки, не «хорошо сделано».
- `literature` — только из паспорта курса.

### Методика

- Активные форматы: кейс, PBL-мини-проект, peer review, исследовательское задание;
  где уместно — с местным контекстом и ЦУР паспорта.
- Задание должно проверять РО на его уровне Блума: РО «проектирует» — задание на
  проектирование, а не пересказ.
- Против списывания и ИИ-генерации: персональные данные варианта, устная защита,
  промежуточные артефакты (черновик, схема), рефлексия о процессе.
- Баллы: сумма по заданиям вида должна сходиться с весом этого вида в `assessment`
  паспорта (например, «Текущий контроль (лабораторные) — 30»). Не сходится — скажи.

## 3. Собери docx

```
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/build_srs.py" "<папка курса>/srs.yaml"
```

Результат — `out/srs.docx`: титульный лист, вступление, сводный график (тема, вид,
неделя, срок, часы, баллы), каждое задание с новой страницы, рубрика таблицей.

Предупреждения скрипта (нет критериев, РО не из паспорта, срок вне семестра, часы СРС
не сходятся с паспортом, источник не из паспорта) — исправь или перечисли преподавателю.

## 4. Самопроверка и итог

Пройди `references/checklist.md`, покажи результат списком (✓ / !).

Затем — путь к файлу и одна следующая команда: «соберите УМКД: `/academic-core:umkd`»
(задания из `srs.yaml` войдут в разделы «Планы практических и лабораторных занятий» и «СРС»).
