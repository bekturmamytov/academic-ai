# Формат srs.yaml

Файл лежит в папке курса рядом с `course.yaml`.

```yaml
title: ""            # необязательно; по умолчанию «Задания для самостоятельной работы…»
intro: |             # необязательно: вступление (абзацы через пустую строку)
  Самостоятельная работа закрепляет материал лекций…
output: srs.docx     # необязательно: имя файла в out/
tasks:
  - week: 1                        # неделя темы
    topic: "Введение в базы данных. СУБД"
    kind: "СРС"                    # СРС | Практическое занятие | Лабораторная работа
    goal: "Научиться сравнивать СУБД по существенным критериям"
    outcomes: [РО1]                # коды из паспорта
    sdg: [4]                       # необязательно
    task: |                        # абзацы через пустую строку, **жирный** работает
      Сравните три СУБД…
    steps:
      - "Выберите три СУБД…"
      - "Заполните таблицу…"
    submission: "Таблица и вывод в docx, загрузить в LMS"
    deadline_week: 2
    hours: 4
    max_points: 10                 # необязательно: сверка с суммой критериев
    criteria:
      - criterion: "Полнота сравнения"
        points: 4
        levels:
          excellent: "все 5 критериев для 3 СУБД"
          good: "пропущены 1–2 ячейки"
          satisfactory: "заполнена половина"
          poor: "меньше половины"
    literature:
      - "Текст записи из паспорта курса"
```

## Как скрипт различает виды

- В `kind` есть «практ», «лаб», «семинар» — задание идёт в раздел УМКД «Планы
  практических и лабораторных занятий».
- Остальное (СРС, СӨИ) — в раздел «Самостоятельная работа студентов»; часы таких
  заданий сверяются с `hours.srs` паспорта.

## Рубрика

Четыре уровня — «Отлично / Хорошо / Удовл. / Неудовл.» — по шкале КР (A–B / C / D–E / F).
Уровень описывает **наблюдаемый результат**: что есть в работе, сколько, какого качества.
