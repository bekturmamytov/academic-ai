# УМКД дисциплины

УМКД — папка документов по дисциплине для кафедры и проверок. Мы собираем её в один
docx из того, что уже сделано, и честно показываем пробелы. Структура и что в каждом
разделе — прочитай `references/umkd-structure.md`.

Говори на языке преподавателя (ru или ky), вопросы — по одному.

## 1. Инвентаризация

1. Найди `course.yaml`. Нет — `/academic-core:new-course`: без паспорта УМКД не собрать.
2. Сначала собери как есть — скрипт покажет статус разделов:

   ```
   uv run "${CLAUDE_PLUGIN_ROOT}/scripts/build_umkd.py" "<папка курса>/course.yaml"
   ```

3. Покажи преподавателю таблицу: раздел — готово / черновик / нет — чем сделать.
   Спроси: «Доделаем недостающее сейчас или соберём как есть? (доделаем)».

## 2. Доделать недостающее

Каждый раздел — своей командой, по одной за раз (спрашивай, с чего начать):

| Нет раздела | Команда |
|---|---|
| Силлабус | `/academic-core:syllabus` |
| Конспект лекций (все темы) | `/academic-core:lecture` — режим «курс лекций» |
| Планы практических / лабораторных, СРС с критериями | `/academic-core:srs` |
| Тестовые задания | `/academic-core:tests` |
| Глоссарий, вопросы к РК и экзамену, методические указания | этот skill — `umkd.yaml`, шаг 3 |

## 3. Напиши `umkd.yaml` (в папке курса)

Без него скрипт ставит черновики по шаблону (вопросы «Объясните суть темы…», типовые
указания). Сделай лучше — образец `templates/umkd.example.yaml`:

- `glossary` — термины, которых нет в лекциях (из лекций скрипт берёт раздел «Ключевые
  понятия» сам). Определения — из лекций и материалов преподавателя.
- `midterm_questions` — `1:`, `2:` … по номеру рубежного контроля (порядок в `assessment`
  паспорта); вопросы только по темам до его недели; 10–20 на РК.
- `exam_questions` — 25–40 вопросов по всем темам; уровни Блума — как у РО паспорта
  (не только «перечислите»: «сравните», «оцените», «предложите решение»).
- `guidelines` — методические указания студентам (Markdown): как работать с лекциями,
  перевёрнутым классом, СРС, как готовиться к контролю, политика ИИ и сроков из паспорта.

## 4. Собери и проверь

Пересобери той же командой. Результат — `out/umkd.docx`: титул с «УТВЕРЖДАЮ»,
оглавление (обновится при открытии в Word), разделы по порядку. Готовые docx
(силлабус, тесты) вклеиваются без их титульных листов; ключ тестов `tests_key.docx`
в УМКД не входит — он хранится отдельно. РУП (`rup.xlsx`) — приложение отдельным файлом.

## 5. Самопроверка и итог

Пройди `references/checklist.md`, покажи результат списком. Отдельно — что
остаётся сделать руками: подписи и протоколы в листе согласования, дата «УТВЕРЖДАЮ».

Затем — путь к файлу и одна следующая команда (первая из недостающих), например
«тесты: `/academic-core:tests`».
