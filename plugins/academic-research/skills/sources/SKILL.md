# Литература: найти, проверить, оформить

Говори на языке пользователя (ru или ky), простыми словами. Вопросы — по одному.

Главное правило: **ни одной ссылки по памяти.** Любое описание источника
берётся из реестра (Crossref, doi.org, OpenAlex), со страницы, которую дал
пользователь, или из его файла. `verified: true` ставит только
`verify_sources.py` — ни ты, ни пользователь руками это поле не правите.
Если ты «помнишь» классическую работу — всё равно найди её скриптом и проверь.

Прочитай `${CLAUDE_PLUGIN_ROOT}/references/sources-schema.md`.
Список лежит в `<папка работы>/sources.yaml` (нет папки работы — спроси, куда
сохранить, или предложи `/academic-research:new-work`).

## Что нужно пользователю?

Спроси одним вопросом: найти литературу по теме · проверить готовый список ·
оформить список по стилю.

## A. Найти

1. Уточни тему и 2–3 запроса: по-русски и по-английски (в OpenAlex английских
   работ больше). Годы — по умолчанию последние 10 лет.
2. Запусти:
   ```
   uv run "${CLAUDE_PLUGIN_ROOT}/scripts/find_sources.py" "<запрос>" --limit 10 --from-year 2016 [--lang ru] --yaml "<папка работы>/candidates.yaml"
   ```
3. Покажи кандидатов нумерованным списком (авторы, год, заглавие, издание, DOI,
   цитирования). Не оценивай содержание работ, которых не читал, — только то,
   что видно из записи.
4. Пользователь выбирает номера → перенеси эти записи из `candidates.yaml` в
   `sources.yaml` без изменений и запусти проверку (раздел B, шаг 2).
5. **КиберЛенинка, eLibrary** — API нет. Скажи: «Найдите статью на
   cyberleninka.ru / elibrary.ru и пришлите ссылку (и DOI, если есть)». Запиши
   `origin: cyberleninka | elibrary`, `url`, выходные данные со страницы — и
   проверь. eLibrary закрыт для скриптов: без DOI нужен файл статьи (`file`)
   или ссылка на сайт журнала.
6. Законы КР — ссылка на cbd.minjust.gov.kg, `type: law`, `note` — вид и дата акта.

## B. Проверить готовый список

1. Получи список: текст в чате, docx (`uv run "${CLAUDE_PLUGIN_ROOT}/scripts/read_doc.py" "<файл>.docx"`)
   или PDF (прочитай сам). Разбери каждую запись в `sources.yaml` **так, как
   написал пользователь** — не исправляй заглавия, годы и DOI «как правильно».
2. Запусти:
   ```
   uv run "${CLAUDE_PLUGIN_ROOT}/scripts/verify_sources.py" "<папка работы>/sources.yaml"
   ```
3. Покажи таблицу: № · источник · ПРОВЕРЕНО / НЕ ПРОВЕРЕНО · чем · что не так.
4. По каждой непроверенной объясни причину и что сделать:
   - DOI не найден → «такого DOI нет; пришлите ссылку на статью или файл»;
   - DOI ведёт на другую работу → «DOI от другой статьи — проверьте запись»;
   - похожая запись есть, но год / автор другой → покажи, что нашлось, и спроси;
   - ничего не найдено → «возможно, такой работы нет; нужна ссылка или файл».
   Скрипт может подсказать работу с тем же заглавием и другим DOI — предложи
   замену, но запись меняй только после согласия и снова проверяй.
5. Нет связи с интернетом — так и скажи: ничего не помечено проверенным.

## C. Оформить

```
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/format_refs.py" "<папка работы>/sources.yaml" --style gost|apa|ieee [--md]
```

В список идут только проверенные; непроверенные скрипт печатает отдельно с
`[НЕ ПРОВЕРЕНО]`. ГОСТ и APA — по алфавиту (кириллица впереди), IEEE — по
порядку ссылок. В тексте глав ссылки ставятся как `[@key]`, `[@key, с. 25]` —
номера расставит `build_docx.py`.

## Самопроверка

Пройди `references/checklist.md`, покажи найденное списком. Итог: сколько
проверено из скольки, путь к `sources.yaml`, одна следующая команда
(`/academic-research:paper` или `/academic-research:thesis`).
