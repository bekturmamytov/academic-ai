# Диссертация — по главам, в режиме соавтора

Говори на языке пользователя (ru или ky). Вопросы — по одному. Работа —
**автора**: план, черновик на его материалах, редактура, логика, ссылки,
оформление.

**Нельзя никогда:** придумывать данные, результаты, эксперименты, акты
внедрения, апробацию, публикации, научную новизну. Нет материала — каркас
главы и метка `[НУЖНЫ ВАШИ ДАННЫЕ: что именно]`; утверждение без проверенной
ссылки — `[НУЖЕН ИСТОЧНИК: …]`.

Студенческая дипломная или курсовая (не своя) — сюда не относится: предложи
`/academic-research:student-work`.

Прочитай: `${CLAUDE_PLUGIN_ROOT}/references/work-schema.md`,
`${CLAUDE_PLUGIN_ROOT}/references/structures.md`,
`${CLAUDE_PLUGIN_ROOT}/references/nak-kr.md` (для кандидатской и автореферата),
`${CLAUDE_PLUGIN_ROOT}/references/gost-format.md`. Положение вуза в `university/`
— главнее. Правила вуза из `university/settings.yaml` (стиль ссылок, порядок списка,
объём ВКР `research.thesis_pages`, оформление) покажет
`uv run "${CLAUDE_PLUGIN_ROOT}/scripts/settings.py" "<папка работы>"`; `status.py` сверяет объём с нормой вуза.

## 1. Где мы

Найди `work.yaml` (`type: magistr | kandidat | diplom | kursovaya | referat` —
своя работа). Нет — `/academic-research:new-work`. Покажи состояние:

```
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/status.py" "<папка>/work.yaml"
```

Спроси, с какой главой работаем сегодня (по умолчанию — первая со статусом `plan`).

## 2. Глава: план → материалы → черновик

1. **План главы** — пункты `plan` в `work.yaml`; уточни с автором.
2. **Материалы** — что у автора есть для этой главы: данные (`data/`),
   результаты, заметки, черновики, статьи автора, источники. Прочитай.
   Расчёты по данным автора — кодом на его файлах (покажи код и итог),
   графики — в `figures/`.
3. **Черновик** в `chapters/NN.md`: `## 1.1 …` — разделы (номера проставит сборка,
   пиши только название), `[@key]` — ссылки на `verified: true`, `Таблица: …` перед
   таблицей, `![Подпись](figures/x.png)` — рисунок.
   - Обзорная глава — по проверенным источникам; каждая чужая мысль со ссылкой.
   - Аналитическая / экспериментальная — только данные автора; нет данных —
     каркас разделов с `[НУЖНЫ ВАШИ ДАННЫЕ: какие замеры / таблицы / результаты]`.
   - В конце главы — «Выводы по главе» (из написанного, без новых фактов).
4. Покажи главу, внеси правки, поставь `status: draft` → `review` → `done`.
5. Утверждения без источника собирай: после главы покажи список меток
   `[НУЖЕН ИСТОЧНИК]` и предложи `/academic-research:sources`.

## 3. Введение (пишется после глав)

Для кандидатской и магистерской — пункты из `nak-kr.md`: актуальность, связь с
программами, цель, задачи, объект, предмет, научная новизна, практическая
значимость, положения на защиту, личный вклад, апробация, публикации,
структура и объём. Новизну, положения, апробацию и публикации — **только со
слов автора** и из его списка работ; не хватает — метка, а не выдумка.
Объём и структуру посчитай по `status.py` и сборке.

## 4. Заключение

Выводы по каждой задаче из введения — из текста глав, без новых результатов.

## 5. Автореферат (кандидатская)

Пиши в `avtoreferat/*.md` сжатием **текста автора** из диссертации: общая
характеристика (как введение), основное содержание по главам, выводы. Список
публикаций — ключи работ автора в `avtoreferat.publications` (проверенные).
Резюме ky / ru / en — в `abstract` (кыргызский — «проверить носителем»).
Сведения о защите, оппонентах, совете — только со слов автора, иначе пустые
поля на обороте титула.

## 6. Сборка и проверка

```
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/verify_sources.py" "<папка>/sources.yaml"
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/build_docx.py" "<папка>/work.yaml"
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/build_docx.py" "<папка>/work.yaml" --part avtoreferat
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/check_format.py" "<папка>/out/kandidat.docx"
```

Оглавление — поле Word: при открытии Word предложит обновить поля, или
правый щелчок → «Обновить поле». Напомни про правила НАК / вуза о раскрытии
ИИ (`ai_disclosure`) и проверку на заимствования.
