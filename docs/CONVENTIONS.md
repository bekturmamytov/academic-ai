# Как пишем skills academicAI

Правила для разработчика (и агента), который добавляет или правит skill.
Решения продукта — в `SPEC.md`, здесь — как их воплощать единообразно.

## Skill

```
plugins/<плагин>/skills/<имя>/
  SKILL.md          ← frontmatter name + description, затем инструкция
  references/       ← нормы, структуры документов, чек-листы (читаются по ссылке)
  templates/        ← YAML-заготовки, Typst-шаблоны
```

- `name` — латиница, kebab-case; команда пользователя — `/<плагин>:<имя>`.
- `description` — по-русски, «что делает» + «используй, когда …» с фразами, как
  скажет преподаватель (ru и ky): «составь силабус», «силлабус түз».
- Тело SKILL.md — до ~250 строк. Длинное (нормы, структура, примеры) — в
  `references/` и ссылкой «прочитай `references/x.md`».
- Пользователь — преподаватель, не программист. Говорим на его языке (ru/ky),
  простыми словами, вопросы — **по одному**, с вариантом по умолчанию.
- Каждый skill заканчивается **самопроверкой** по чек-листу
  (`references/checklist.md`) и показывает найденное списком; затем — путь
  к файлу и одна следующая команда.

## Данные

- Курс: `<папка курса>/course.yaml` — схема `plugins/academic-core/references/course-schema.md`,
  пример `plugins/academic-core/templates/course.example.yaml`.
- Преподаватель: `profile.yaml` в рабочей папке (или выше по дереву), схема — в skill `academic:setup`.
- Вуз: `university/` в рабочей папке — `brand.yaml` (`name`, `name_ky`, `name_en`,
  `logo`, `color`), положения вуза (docx/pdf) — необязательно.
- Наука: `<папка работы>/work.yaml` — схема в `plugins/academic-research/references/work-schema.md`.
- Промежуточные данные skill пишет в YAML рядом (`tests.yaml`, `lectures/NN.md`),
  итоговые файлы — в `out/`.
- Новый skill не придумывает свои поля паспорта — если нужно поле, добавь его в
  схему и пример.

## Скрипты

- Python 3.10+, один файл = одна команда, зависимости — inline-метаданными PEP 723:

  ```python
  # /// script
  # requires-python = ">=3.10"
  # dependencies = ["python-docx>=1.1", "pyyaml>=6"]
  # ///
  ```

- Запуск из SKILL.md всегда так (работает на macOS и Windows):

  ```
  uv run "${CLAUDE_PLUGIN_ROOT}/scripts/build_syllabus.py" "<путь к course.yaml>"
  ```

  `uv` ставит `/academic:setup`. Без глобального pip, без venv руками.
- Скрипт печатает путь к готовому файлу и предупреждения; ошибки данных —
  понятным текстом по-русски, код возврата ≠ 0.
- Пути — `pathlib`, кодировка `utf-8`, никаких bash-only команд.
- Скрипты плагина лежат в `plugins/<плагин>/scripts/`; между плагинами пути не
  делим (у каждого свой `${CLAUDE_PLUGIN_ROOT}`) — нужен общий код, копируем
  маленький модуль.
- Тест скрипта — `plugins/<плагин>/tests/` (pytest через `uv run --with pytest`),
  на примере `course.example.yaml`.

## Оформление документов

- Официальные docx: Times New Roman 14 (таблицы 12), интервал 1,5 (таблицы 1,0),
  поля: левое 30 мм, правое 15, верх/низ 20; абзацный отступ 1,25 см;
  выравнивание по ширине; нумерация страниц внизу по центру.
- Титульный лист: министерство, вуз (из `university/brand.yaml` или `profile.yaml`),
  факультет, кафедра, «УТВЕРЖДАЮ» (для силабуса/РУП/УМКД), название, город, год.
- Подписи по-языку: тексты-метки (заголовки разделов, «Утверждаю», «Кредиты»)
  — в словаре `scripts/i18n.py` с ключами ru/ky/en, не зашиты в код по месту.
- Никакого «academicAI» / «AI Lab» в документах пользователя.
- Презентации: 16:9, белый фон, один акцентный цвет (`brand.yaml` → `color`,
  по умолчанию `#1F4E79`), заголовок ≤ 8 слов, ≤ 6 пунктов на слайд, заметки
  докладчика — полный текст.

## Честность

- Литература: только `verified: true` попадает в чистовик; иначе
  `[НЕ ПРОВЕРЕНО]` и предупреждение.
- Данные исследований, цифры, результаты, цитаты — не выдумываем.
- Студенческие работы — задание, методичка, критерии, рецензия.

## Evals

`plugins/<плагин>/evals/<кейс>/case.yaml` — 1–3 кейса на ключевой skill,
запуск `claude plugin eval plugins/<плагин>`.
